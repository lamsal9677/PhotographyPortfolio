# Connect your editor and publish the portfolio

The repository already contains the content model, Pages CMS configuration, build script, tests, and GitHub Pages workflow. Your remaining steps happen in your GitHub and Pages CMS accounts.

## 1. Enable GitHub Pages

1. Open https://github.com/lamsal9677/PhotographyPortfolio/settings/pages.
2. Under **Build and deployment**, select **GitHub Actions** as the source.
3. If GitHub says your account needs an upgrade for Pages on a private repository, pause and choose whether to use a paid eligible plan or make the repository public. Do not change repository visibility without considering that photos and drafts become readable.
4. Leave the custom-domain field empty for this first test.

## 2. Turn publishing on

1. Open the repository's **Settings → Secrets and variables → Actions → Variables**.
2. Select **New repository variable**.
3. Set the name to `PAGES_ENABLED` and value to `true` (lowercase).
4. Save it.
5. Open **Actions → Build and publish portfolio → Run workflow**.
6. Choose `main` and run it. Wait for both `build` and `deploy` to turn green.
7. Open the URL shown by the deployment, expected to be https://lamsal9677.github.io/PhotographyPortfolio/.

The variable is not a secret. It is an explicit publishing switch. No personal access token is needed; GitHub provides a short-lived workflow token.

## 3. Connect Pages CMS

1. Open https://app.pagescms.org.
2. Select **Sign in with GitHub** and use your `lamsal9677` account.
3. Follow the GitHub App installation prompt.
4. Choose **Only select repositories**, then select **PhotographyPortfolio**. Review the requested permissions before approving.
5. Return to Pages CMS and open **lamsal9677/PhotographyPortfolio**, branch **main**.
6. It should read `.pages.yml` automatically. You should see **Collections**, **Stories / Field notes**, and **Site settings**. Do not replace the configuration with an autogenerated example.

If you cannot see the repository, check the GitHub App installation's selected repositories. If you see only a raw-file editor, check that you opened the correct repository and branch.

## 4. Make a harmless first edit

1. In **Site settings**, make a small change to your biography.
2. Save the change.
3. In GitHub, open **Actions** and wait for the new build and deployment to finish.
4. Reload the GitHub Pages URL and verify the edit.

Saving in the editor commits a change to GitHub. Updates appear on the website only after that build and deployment succeed. A failed build leaves the previous deployed version in place.

## 5. Add a collection

1. Choose **Collections → New**.
2. Enter a title and use a simple lowercase filename such as `graduation-session.json`.
3. Choose the section: **People & events** or **Nature**.
4. Choose the category. Nature supports Landscapes, Birds, Wildlife, or Small worlds. For event work, choose People & events.
5. Set **Display order**; lower numbers appear first.
6. Add photographs to the list. For each one, upload or select an image, describe it for accessibility, and optionally add a caption or short field note.
7. Turn **Feature among collection highlights** on for the strongest few. If none are selected, the first three are used.
8. Set a cover that is also included in the photograph list.
9. Leave **Publish on website** off while preparing it. When ready, turn it on and save.

Upload JPG, PNG, or WebP exports suitable for a public portfolio. The build creates smaller versions and reads dimensions; you do not have to create thumbnail files or enter aspect ratios.

To change collection order or photo order, edit its display number or reorder its photo list. Changing a cover does not change the list order.

## 6. Write a story

1. Choose **Stories / Field notes → New**.
2. Enter a title, category, optional date and broad location, and select a cover.
3. Write a short introduction and your story. Separate paragraphs with a blank line. This first version uses plain text, not HTML or a rich-text editor.
4. Optionally add photographs with captions. You can select images already in your portfolio; no second upload is needed.
5. Turn on **Publish on website** and save when ready.

A published story gets a page at `stories/<filename>/`, appears on the Stories page (not the homepage), and is linked from the cover photo and included photographs in the viewer. Event stories work the same way as wildlife stories. If more than one story uses the same photo, the current viewer displays one related-story link.

Drafts are excluded from the deployed site but are not private in a public repository. Do not write private notes, client information, or precise sensitive wildlife coordinates in repository files.

## 7. Connect lamsal.photos after testing

1. Verify the GitHub Pages site, galleries, and first content edit before touching DNS.
2. In GitHub account settings, verify ownership of `lamsal.photos` for Pages.
3. Set `lamsal.photos` as the custom domain in the repository's Pages settings.
4. At your domain provider, add the exact DNS records from GitHub's current instructions. Preserve unrelated email/MX/TXT records.
5. Once GitHub's DNS check passes, enable **Enforce HTTPS**.
6. In Pages CMS **Site settings**, change the public website URL to `https://lamsal.photos` and save.

Changing the Pages CMS site URL does not move the domain by itself. Keep the existing site running until the new host is verified.
